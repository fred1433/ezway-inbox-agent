      What runs behind it

      • It lives in one Gmail account. A Google Apps Script, authorized by the owner of that mailbox, checks for new mail on a timer and works through a small batch each time. Rolling it out to more of the team depends on which inboxes receive these emails and who owns the sheets.
      • The code never sends. It has no send operation. Replies are created as drafts in the same thread, for someone on the team to read and send.
      • Listing facts are inserted from the listing record. Changes proposed in an email are quoted from that email and queued for review. A check rejects drafts whose wording goes beyond the facts the code inserted. It is a guard, not a proof; a person reviews every draft.
      • It writes little on its own. New contacts, leads and interactions, and last-contact dates. A new closing date, price or term goes to a Review tab and the current value stays where it is.
      • Each message is logged; a retry resumes the saved plan instead of redoing it (tested with simulated failures). If the script finds its own draft for a message, it does not create another. Only mail received after installation is read, and messages from the mailbox owner or an alias are not treated as incoming.
